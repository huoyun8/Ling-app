# SnapCore / SnapOCR · 截图标注 / 二维码 / 文字识别（C 版）

Windows 10/11 上的轻量工具。**一份源码出两个产品**，只差一个编译宏：

| 产品 | 页签（从左到右） | 说明 |
| --- | --- | --- |
| **SnapCore** | 二维码 / 文件校验 / 文件改名 / 定时关机 / 设置 | 不带 OCR 引擎，exe 约 1.6MB（版本 1.0） |
| **SnapOCR** | 文字识别 / 二维码 / 文件校验 / 文件改名 / 定时关机 / 设置 | 内嵌 PP-OCRv6，exe 约 33MB（版本 2.0） |

两者另有截图标注（框选 / 标注 / 贴屏 / 录屏）、文件校验（MD5 / SHA256 / CRC32）、电脑定时关机、压缩软件一键全关、压缩包防多开。单文件、免安装、不联网。

品牌名由 `Src/Brand.h` 按 `SNAPCORE_WITH_OCR` 派生（窗口类名、单实例标识、配置目录、启动项、任务栏 ID 全部带品牌前缀），所以两个版本可以**同机安装、同时运行**，互不抢热键注册、互不覆盖配置。

C++20 / Win32 / Direct2D。界面全部自绘（`Src/Ui/`：自写 flex 布局 + WinRT Composition 呈现）。语言包只有中文，编译期以 RCDATA 嵌入 exe，不带外部语言文件。

## 启动方式

| 启动 | 表现 |
| --- | --- |
| 双击 exe（不带参数） | **只挂托盘**，不弹主界面 |
| 再双击一次 exe | 已有实例把主界面亮出来（防多开：第二个进程把请求转过去后自己退出） |
| `--auto-start` / `--enter=tray` | 只挂托盘，不建主窗口（开机自启走这条） |
| `--enter=shot` | 直接进框选，不摆主界面 |
| `--enter=pin` | 框选完直奔贴屏（等于替用户按住 Ctrl） |
| `--auto-quit=true` | 用完即走：截完（或贴屏窗口关完）进程自己退出 |

参数可叠加，例如 `--enter=pin --auto-quit=true`。

## 主界面（SnapOCR 六页 / SnapCore 五页）

窗口客户区 585×445@96dpi，全部坐标过 DPI 换算；在主界面任意状态按 `Esc` 收进托盘。

> 下面第 1 节「文字识别」只有 **SnapOCR** 有（`SNAPCORE_WITH_OCR` 定义时）。
> **SnapCore** 的首页是第 2 节「二维码」，页签少一颗，其余四页完全相同，
> 识别热键在 SnapCore 上只做「截一段屏幕认二维码」，没有文字识别可回落。

### 1. 文字识别（仅 SnapOCR）
- **识别**（或按 `F2`）：框选屏幕任意区域 → 文字进来。纯手动框选，不做智能吸附。
- **排版**：点一下切一档，四档循环「自动合并 → 每框一行 → 合并成一段 → 引擎原始顺序」。切档位是**用刚识别时的坐标重排，不重新识别**，所以是瞬时的；档位记进配置，下次启动还在。
  - **自动合并**（默认）：双栏网页先读左栏再读右栏，连续的行合成自然段，竖排从右往左读。
  - **每框一行**：每个文本框各占一行，只按阅读顺序排 —— 表格、列表、代码用这档。
  - **合并成一段**：全部连成一行，适合只取一个短语。
  - **原始顺序**：引擎给什么顺序就是什么顺序（引擎直出），排障对照用。
- **查找**：在已识别文本里定位并选中（不区分英文大小写），找不到会提示。
- **复制 / 清空**：整块复制到剪贴板 / 清掉结果（同时丢掉缓存的坐标，切档位不会把旧字排回来）。**清空按钮是红色**，跟别处的清空一致，避免误点。
- 右下角实时字数。识别在工作线程里跑，界面不假死；引擎进程空闲 3 分钟自动回收。

### 2. 二维码
- **生成**：输入文字 / URL → 实时生成二维码。输入框为空时右侧常驻一张示例码（内容为「请输入文本内容！」），不会变成空白卡片。
- **识别二维码**：框选屏幕任意区域，从像素里解码；识别结果直接回填输入框。纯手动框选，不做智能吸附。**这一块里没有二维码时自动回落文字识别**，识别结果填进输入框并生成二维码。
- **`F2`（识别键）在这一页的行为**：先当扫码用；这一块里**没有二维码时自动回落文字识别**，识别结果直接填进输入框并生成二维码 —— 等于「截一段文字 → 变成二维码」一步到位。
- **复制二维码**：把当前码作为图片放进剪贴板。
- **下载二维码**：另存 PNG。
- **上传 LOGO**：给码中心嵌一张 PNG（仅支持 PNG）。
- **清空**：清掉输入，回到示例码。
- **截图**：直接从截图流程进入标注（与 `F1` 同一条入口）。
- **关闭压缩软件**：一次点击扫一遍，用 `WM_CLOSE` 优雅结束正在运行的压缩软件主程序（WinRAR / 7-Zip / Bandizip / 360压缩 等 GUI 版）。命令行版 `7z.exe` / `rar.exe` 不在名单里，避免误伤别处在用的解压进程。不做后台常驻。

### 3. 文件校验
- **浏览…**选择或直接把文件拖进窗口，计算 **MD5 / SHA256 / CRC32**；可勾选同时显示版本号与修改日期。
- **文件 / 总计**两条进度条：上面是当前文件，下面是整批；一次拖入多个按总字节推进。
- **两次对比**：结果框的**整圈外框**告诉你结论——绿色＝相同，红色＝不同，浅灰＝没有结论（首次校验 / 校验中）；本轮与上一轮按（算法值 + 路径）指纹比对，不写字、也不占正文宽度。
- 结果框**只保留最新两条记录**（自绘控件，滚动不重叠），「清除」连外框颜色一起复位。
- 一行放不下时（典型是 SHA256 那 72 个字符）自动降一档字号，摘要值不会被截断。
- 大文件在工作线程里算，随时可「停止」，界面不假死。
- **复制 / 保存…**：把当前记录按显示顺序导成纯文本。

### 4. 文件改名
- **文件 / 文件夹**：按钮选，或直接把文件、文件夹拖进窗口。文件夹会递归展开成里面的文件（子目录一并收），重复路径按小写全路径去重。底部状态条显示「共 N 个，待改 M 个」。
- **规则面板**（上排五页切换，点一下就换一组）：
  - **转换**：查找替换（可勾「区分大小写」「替换所有」）、全部大写 / 全部小写 / 首字大写、简繁互转、一二三↔123、汉语转拼音 / 拼音首字母。
  - **前后缀**：增减前缀 / 后缀，可用 `<name>` 原文件名、`<self>` 已生成的新文件名、`<dir>` 文件夹名、`<now>` / `<date>` / `<time>` 当前时间、`<#>` `<##>` 数字占位。
  - **扩展名**：全部大写 / 全部小写 / 不变 / 删除 / 改为指定后缀。
  - **序号**：起始值 / 增量 / 位数。
  - **删除**：勾选要删掉的字符类别（空格 / 小写字母 / 大写字母 / 数字 / 中文 / 特殊字符），再给一个「文本：」框直接删指定片段。
- **表格**四列：序号 / 文件名 / 新文件名 / 状态。状态分就绪、同名、无效（文件名含非法字符或以点、空格结尾）、冲突（同目录里撞名）、不存在。**双击「新文件名」那一列可以就地改**，改完按回车落定、`Esc` 放弃。
- **勾选**：行首方框决定这一行是否参与改名；底部「全选 / 反选」批量勾。**过滤**下拉按扩展名筛（全部格式或某个后缀），只影响列表显示。
- **执行改名**走两阶段：先把待改的全部改成临时名，再改成目标名 —— 所以 a↔b 互相交换不会覆盖，中途任何一步失败就整体回滚并提示「改名失败，已回滚」。
- **撤销**只回滚上一次「执行改名」成功的批次；**重置**把规则清回默认（不动列表）；**复制**把新文件名按顺序放进剪贴板；**刷新**重新读盘，文件在资源管理器里被删 / 改名后用它对上。

### 5. 定时关机
- 「天 / 时 / 分 / 秒」倒计时，到点自动关机（已启用 `SE_SHUTDOWN_NAME` 权限）。
- **开始定时器**后「清空」置灰；**暂停定时器**后恢复可点 —— 防止跑到一半被一键清零。
- 倒计时以「截止时刻」反算（`GetTickCount64`），机器睡眠期间跟着停，不会越跑越慢。
- 状态条本身是进度条：暂停时保留已走过的比例，不归零。
- 四个格子手输上限统一 99，离开输入框即夹到合法值并补零；▲▼ 步进按各自格子（时 23、分 / 秒 59）。
- 最后 10 秒把主界面顶到前台并切到本页，给一次「暂停 / 重设」的机会。

### 6. 设置
- **截图保存 / 视频保存**：两行各显示当前目录（默认桌面），右侧「更改…」弹系统的选择文件夹对话框。目录被删或盘不在时会自动回落到桌面；设置页显示的就是实际落盘的目录，不会出现"这里写 D:\、文件却落在桌面"。
- **常规组五颗勾选**（文案都压到 5～6 字）：**开机自启**、**压缩包防多开**（默认开）、**截图时隐藏**（默认开）、**关闭到托盘**（默认开，关掉后点关闭 = 退出进程）、**只允许单实例**（默认开）。
  - 压缩包防多开：后台只看一件事 —— 同一个压缩包被开出多个窗口时，只留最新打开的那个（比较进程创建时间 → 首次出现时刻 → z 序），其余 `WM_CLOSE`。与二维码页那颗「关闭压缩软件」不是一回事：**按钮是点一次全关，看护是常驻只去重**。
  - 只允许单实例：勾上时第二次启动只把已在跑的窗口亮出来然后自己退出；**取消勾选**后可以同时开多个，每个进程各有一套托盘与热键（热键是全局独占，后开那个若撞键会提示注册失败），`config.json` 以最后一次写入为准。这个开关只影响之后启动的进程。
- **三行快捷键录入**（截图 / 识别 / 压缩软件全关）。点「录制」期间所有已设置的快捷键临时失效，录完或按 `Esc` 恢复；
  **清空某一项**：点「录制」再按 `Delete`，或者直接点一下那行的框按 `Delete` / `退格`。「识别」这一行就是原来的「扫码」，改的只是名字和它在新版本里的职责。每行右侧是一只「副编辑器」：点一下进入录入，格内直接显示「请按键… / 已保存 / 未设置」，不弹独立浮层；录入期间所有热键暂时注销，走完自动恢复。
- 四组热键共用一张组合池（`cap` / `qrcap` / `hide` / `zipkill`），**互为排他**：新设的组合若已被别的功能占用，会直接把占用方清空并立刻注销，不会出现「两处写着同一个键、实际只有一个响」。

## 录屏

截图后在工具条点「录屏」开始录制：

- 格式 MP4 / GIF 可切换（点格式按钮切换）。**MP4 支持录系统声音、录麦克风**；GIF 不带音频。
- 上限：MP4 最长 10 分钟，GIF 2 分钟（到时自动收尾）。
- GIF 的抓帧与编码分在两条线程：抓帧只做 BitBlt + 转 RGB + 入队，量化 / 差分 / 写盘（cgif）在独立线程上跑，队列有界（最多 8 帧、约 64MB）且缓冲复用，编码慢也不会把抓帧拖成掉帧。
- 结束三选一：**停止并丢弃 / 停止并保存 / 停止并复制到剪贴板**（保存目录在设置页指定，默认桌面）。
- 录制中按 `Esc` 直接丢弃并退窗。
- 保存成功后在软件内弹一条半透明轻提示「已保存」，不打断操作。

## 其它既有能力

- **框选**：窗口 / 控件 / 像素边缘智能吸附、滚轮切换候选。吸附只服务**第一次选区**（悬停预览与首次拖框）；选区一旦落定，再拖边角或整体移动就是纯鼠标跟随，不再贴边。
- **标注**：矩形 / 椭圆 / 箭头 / 标号 / 直线 / 文本 / 马赛克（含高斯模糊）/ 橡皮擦，带填充与颜色。
- **取色**、**贴屏**（钉在桌面、可拖动缩放）。

## 边界说明

- **不联网**：没有网络导入、没有更新检查，exe 里不含 wininet / WinSock / URLMON 依赖。
- **单实例**：第二个实例只把请求转给已有进程，自己退出（秒退不是崩）。
- **语言**：只有简体中文，编进 exe。
- 托盘右键菜单：打开主界面 / 设置 / 退出。

## 构建

**命令行（本机唯一可用路径，msbuild 被安全策略拦截）**：

```bash
./build.sh                        # 增量构建，产物 build/bin/<品牌>.exe
./build.sh clean                  # 全量重建（改 .h 触发 PCH 重建，等同全量）
SNAPCORE_WITH_OCR=0 ./build.sh    # 出 SnapCore.exe：不含「文字识别」页、不编 Src/Ocr/*、不内嵌模型
SNAPCORE_WITH_OCR=1 ./build.sh    # 出 SnapOCR.exe：内嵌 PP-OCRv6（压缩后约 32MB）
SNAPCORE_OCR_EMBED=0 ./build.sh   # 带引擎但不内嵌模型（开发用；产物旁边要放 ocr\ 目录）
```

不带 `SNAPCORE_WITH_OCR` 时按**目录名**判定：`SnapOCR/` 走带引擎那版，其它名字走 SnapCore。
两个产品的中间产物分放在 `build/obj-SnapCore` 与 `build/obj-SnapOCR`，切产品不会串 obj。

OCR 引擎（PaddleOCR PP-OCRv6 检测+识别、ONNX Runtime）与字典经 LZMS 无损压缩后以 RCDATA 嵌进 exe，
首次识别时释放到 `%LOCALAPPDATA%\<品牌>\ocr`（SnapOCR → `SnapOCR\ocr`），之后复用缓存。裸文件 46.9MB → 压缩后 32.3MB，识别结果与不压缩完全一致。
`Src/Res/ocr/` 放原始模型（det / rec / dict / ocr-process.exe），构建期由 `tools/ocrcmp` 压成 `build/ocrpack/*.bin`。

直接驱动 VS2022 BuildTools 的 `cl.exe` / `link.exe` / `rc.exe`，参数对齐 vcxproj 的 `Release|x64`（`/O2 /GL /MT /std:c++20`）。源码清单由 `find` 收集，删一个 `.cpp` 不必改脚本。

**Visual Studio 2022**（v143，「使用 C++ 的桌面开发」）：打开 `Src/ScreenCapture.vcxproj`，选 `x64 + Release` 生成。以 `build.sh` 链路为准。
