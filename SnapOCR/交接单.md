## 1. 这是什么

Windows 上的截图标注 + 二维码工具箱，带 OCR 的版本多一页文字识别。常驻托盘、单实例、全程不联网。

- **SnapCore**（无 OCR）：五页 —— 二维码 / 文件校验 / 文件改名 / 定时关机 / 设置；exe 约 1.6MB（版本 1.0）
- **SnapOCR**（带 OCR）：六页 —— 文字识别（首页）+ 上面五页；exe 约 33MB（PP-OCRv6 已内嵌，版本 2.0）

技术栈：C++20 / Win32 / Direct2D + DirectWrite / WIC；界面全自绘（`Src/Ui`）；
二维码编码 libqrencode、解码 quirc、GIF 编码 cgif。两版共用一份源码，**唯一分叉点是
`Src/Brand.h` 的 `SNAPCORE_WITH_OCR`**：品牌名、窗口类名、配置目录、启动项全部由它派生。

## 2. 构建

```bash
./build.sh                        # 增量，产物 build/bin/<品牌>.exe
./build.sh clean                  # 全量重建
SNAPCORE_WITH_OCR=0 ./build.sh    # 强制出 SnapCore.exe
SNAPCORE_WITH_OCR=1 ./build.sh    # 强制出 SnapOCR.exe（内嵌模型）
SNAPCORE_OCR_EMBED=0 ./build.sh   # 带引擎但不内嵌模型（开发用，exe 旁放 ocr\ 目录）
```

不设环境变量时按**目录名**判定：`SnapOCR*` 出带引擎版，其余出纯工具版。
中间产物按品牌分放（`build/obj-SnapCore` / `build/obj-SnapOCR`），切产品不会串 obj。

工具链：MSVC 14.44.35207 + Windows SDK 10.0.22621.0，脚本直接驱动 `cl.exe` / `link.exe` /
`rc.exe`。**本机安全策略会拦 msbuild，别改回 msbuild。**

必须知道的坑：

1. bash 不在 PATH，PowerShell 里要显式调 Git bash：
   `& 'C:\Program Files\Git\bin\bash.exe' -lc './build.sh'`（命令用单引号，`$?` 会被插值）。
2. 不同目录禁止同名 `.cpp`（脚本第 0 步直接报错退出）；GUI 层统一 `Ui` 前缀。
3. 源文件编码不统一（多数带 UTF-8 BOM，少数不带）；批量改写前先确认该文件的编码。
4. `Lang/zh-CN.json` 是 UTF-8 + CRLF（无 BOM），以 RCDATA 编进 exe；
   改完必须确认 JSON 合法，解析失败等于启动失败。
5. 改任意 `.h` 会触发 PCH 重建 → 全部源文件重编，这不是卡住。
6. `.vcxproj` 里的条目是相对 `Src/` 的，比对清单时不要再加 `Src/` 前缀。
7. 旧实例先退出；二次启动看着像闪退，其实是把请求转给已有进程（单实例锁）。

## 4. 输入法（IME）定位

「候选框飘到左上角 / 每敲一个字闪一下」收敛成**单一入口**，改动前先读完这一节：

- 四条 IME 消息（`WM_IME_STARTCOMPOSITION` / `WM_IME_COMPOSITION` / `WM_IME_ENDCOMPOSITION` /
  `WM_IME_SETCONTEXT`）在 `Src/Ui/WinBase.cpp` 走同一个分支，统一转 `TextBox::onIME()`。
- 光标矩形由 `placeImeUi()` 算、`syncImeCaret()` 推；`kImeNudge` 是 30ms 一次性定时器，
  用于「输入框刚移动、IME 还没拿到新光标矩形」那一帧补推，推完立刻 kill。
- **不要**再加第二个 `SetTimer` 或另一处 `ImmSetCompositionWindow`：两处都推，
  候选框会在两套坐标间来回跳（历史上的「飘一角」就是这么来的）。

## 5. 文字识别（仅 SnapOCR）

- 起独立进程 `ocr-process.exe`（PaddleOCR PP-OCRv6 small 的 det + rec，ONNX Runtime，CPU 后端），
  走私有协议；结果框、线程调度在 `WinQr` 的文字识别页。**不做表格结构还原**。
- 模型资产（det + rec + 字典 + 引擎，合计 46.9MB）由 `tools/ocrcmp` 以 LZMS 无损压到 32.3MB，
  以 RCDATA 编进 exe；首次识别释放到 `%LOCALAPPDATA%\<品牌>\ocr`（先写 `.part` 再 MoveFileEx，
  按文件大小判断是否已释放）。解出的文件与源文件 MD5 一致。
- DirectML.dll 故意不打包：CPU 后端更快；要用显卡把 dll 丢进 `ocr\` 即可，引擎会自己切后端。
- 排版四档（`common.ocrLayout`）：`auto` 切栏→聚行→自然段 / `line` 每框一行 / `flat` 全拼一段 /
  `raw` 引擎原始顺序。切档位用缓存坐标重排，不重识别。
- 热键不新增：原来的扫码键（默认 `F2`）对外叫「识别」，按当前页分叉 ——
  二维码页先扫码，解不出就回落文字识别并填进输入框；文字识别页纯识别；其它页先切页再识别。
  「识别二维码」按钮与热键走同一个 `qrGrabWithFallback()`。
- 选区是纯手动框选（`cutMask->autoSnap = false`，grab 模式下 `allowSnap()` 恒 false）。

## 6. 录屏

- 工具条「录屏」→ `CapVideo::start()` 起后台编码线程（立刻返回）。
- 格式：MP4（Media Foundation，系统声音 + 可选麦克风）/ GIF（cgif，无音频）。
- 上限：MP4 10 分钟、GIF 2 分钟。
- 收尾：停止并丢弃 / 停止并保存（目录取 `Setting::getVideoDir()`，空则桌面）/ 复制到剪贴板。
- 录制中 `Esc` = 丢弃 + 退窗；保存成功走软件内半透明轻提示，不用状态栏。

## 7. 快捷键口径

- 四组共用一张组合池（`cap` / `qrcap` / `hide` / `zipkill`），**互为排他**：
  新组合被别的组占用时，就把那一组清空并立刻 `unRegHotKey`。
- 默认值：`cap=F1`、`qrcap=F2`、`hide=F10`、`zipkill=空`。
- 设置页只有三行可录（截图 / 识别 / 压缩软件全关）；`hide` 固定 `F10`，不进 UI。
- 清空快捷键两种按法：① 点「录制」再按 Delete / 退格；② 焦点在显示框上直接按 Delete / 退格
  （消息循环层拦截，`WinQr::handleAppKey()`）。
- 录入期间整体注销热键，录完原样注册回来；切页会在 `setPage()` 里把录入收掉。
- 注册结果不记账（没有「未生效」提示与 `*HotkeyOk` 成员）。

## 8. 智能消除与马赛克

- 三种算法共用同一条标注：0 马赛克 / 1 高斯模糊 / 2 智能消除（`ShapeMosaic` 的 `effect`）。
- **动笔画法**：马赛克与高斯模糊都是全分辨率块平均 + 1:1 位图画刷，只做平移不平移缩放，
  不改像素（之前试过的降采样 / 脏则重建方案已废弃）。
- **智能消除只做选框**：它的曲面拟合 + PatchMatch 需要矩形范围，手绘对它没有意义。
  选中智能消除时形状固定为选框，工具条上「选框 / 手绘」那颗按钮置灰、点了不响应
  （第二道闸在按钮回调里）；切走算法后恢复正常。
- 智能消除内部：曲面拟合 → 周期平移 → 金字塔 PatchMatch，工作区上限 4M 像素。

## 9. 已知限制（口径，不按缺陷处理）

1. 非最上层标注不可再编辑（`WinHost::probeHover` 只喂最上层未撤销形状）。
2. 二维码页无容错等级 / 尺寸开关，走内置默认值。
3. 扫码与文字识别都是纯手动框选，不做自动吸附。
4. 文件校验结果框只留最新两条记录；语言只有简体中文。
5. 文字识别不还原表格结构（表格请切 `line` 档）；竖排不做段落合并。
6. 字典 `ppocrv6_dict.txt` 无谚文、无西里尔 —— 韩文 / 俄文 / 越南文不可用；
   中（简繁）/ 英 / 日 / 欧洲拉丁语系实测可用。
7. 不支持自动判方向（0/90/180/270），倒置图需先转正再截。
8. 字号上限三处各自为政（滑条 10–72、拖角到 180 物理、`setFontSize` 换算），当前自洽。

## 10. 验证要点（想复核的话）

| 项 | 结果 |
| --- | --- |
| `Esc` 任意状态退窗 | 121ms 内收窗 |
| 放弃 / 保存 / 复制之后 | 立刻退窗 |
| MP4（带系统声音）/ GIF 录制与上限 | 正常，GIF 2 分钟自动收尾 |
| 内存（24 轮截图 + 标注 + 录屏） | 47.6 ~ 52.4MB，无增长趋势 |
| exe 网络依赖 | 无 wininet / WinSock / URLMON 导入 |
| 启动冒烟 | 托盘启动稳定，工作集 ~12MB（未进 D2D 路径） |
| 编译 | 0 warning |
| 内嵌模型首启释放 | 清空 `%LOCALAPPDATA%` 后自动释放 4 个文件，MD5 与 `Src/Res/ocr/` 一致 |
| 识别出字 / 排版离线自测 | 40 字符逐字正确；双栏 / 段落 / 表格 / 竖排 / raw 全过 |

**人工复核路径**：`./build.sh` → 双击挂托盘 → 再双击出主界面 → 各页各点一遍 →
设置页换保存目录、切四颗勾选、录三行快捷键（故意同组合验互斥）→
`F1` 框选标注 `Enter` → 录屏 MP4 / GIF 各 5 秒 → 定时关机设 10 秒再暂停清空 →
文件校验拖两个文件，再用同文件校验一次（外框应变绿）。

## 11. 缺陷处置记录（只留结论）

| 问题 | 处理 |
| --- | --- |
| IME 候选框飘左上角 / 每字闪一下 | 四条消息收成单一分支，`kImeNudge` 只补推一次 |
| 状态栏提示太吵 | 改软件内半透明轻提示，1.6s 自收 |
| 放弃 / 保存 / 复制后窗口还挂着 | 三条路径都立刻退窗 |
| MP4 没有声音 | 补系统声音与麦克风两路 |
| 空指针隐患（v31 审计） | `WinPin` 构造、`WinCap::getCutImg`、`ShapeText::removeLater` 补判空 |
| 内存只涨不落 | 二维码像素缓冲 / DIB 成员复用；`App::trimMemory()` 挂在截图会话结束 |
| 联网残留 | 删净 wininet / WinSock / URLMON 依赖 |
| vcxproj 缺项 | 补 `cgif` 源文件与九个头文件，`.filters` 同步 |
| 智能消除支持手绘（伪需求） | 固定选框，形状按钮置灰 |
| int8 量化实验链路 | 实测掉精度（相似度 0.86、整屏少 17 行），整条链路（脚本与构建分支）已删除 |
| 撤销后新建会清空重做栈 | 既有设计，不是缺陷（`createShape()` 首行 `removeUndoShape()`） |

**已排除（检查过没有问题）**：`scaleStartDist` 有 `max(1.f, …)` 兜底无除零；
`removeLater` 走延迟队列不在回调里释放自己；`isInRect` 用严格不等号；
撤销 / 重做顺序正确；快捷键四组互斥后立刻 `unRegHotKey`。
